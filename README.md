# MediPredict – MLflow Experiment Tracking and Data Drift Analysis

ISE-2 project for **ML DevOps (UAMPC0703)**. A diabetes-risk model for a small clinic is trained,
tracked with **MLflow**, and then monitored for **data drift** (with supporting prediction-drift and
performance checks) on four *simulated* "current" data windows.

## Use case
| Item | Value |
|---|---|
| Domain | Healthcare – diabetes risk screening for a small clinic |
| Dataset | Pima Indians Diabetes Database (768 records, 8 features + `Outcome`) |
| Model | scikit-learn RandomForest (median imputation + classifier) |
| Drift type | Data drift (primary); prediction drift and performance as supporting evidence |
| Tools | MLflow (tracking + artifacts), SciPy (KS test), NumPy (PSI), Matplotlib |

## Quick start
```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python drift_pipeline.py             # downloads data/diabetes.csv if missing
mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000
```
Open <http://127.0.0.1:5000>. If the automatic download fails, download the CSV manually
(Kaggle: *Pima Indians Diabetes Database*, or UCI), save it as `data/diabetes.csv`, or run
`python drift_pipeline.py --data <path>`.

Record the exact versions for the report: `python --version`, `mlflow --version`, `pip freeze > requirements-lock.txt`.

## What gets logged to MLflow (experiment `MediPredict-Diabetes-Drift`)
| Run | Contents |
|---|---|
| `baseline_training` | model parameters, out-of-fold AUC (reference), hold-out AUC/accuracy/recall/F1, logged model, reference summary |
| `control_no_shift` | random unseen sample – expected **no** drift |
| `population_shift_moderate` | clinic starts seeing older / heavier / higher-glucose patients (selection tilt k = 1.5) |
| `population_shift_severe` | same shift, stronger (k = 3.0) |
| `glucose_unit_change` | Glucose recorded in mmol/L instead of mg/dL (data-quality drift) |
| `summary_all_scenarios` | `drift_summary.csv` |

Each scenario run records PSI and KS p-value per feature, number/share of drifted features, alert level,
predicted-risk mean and KS test (prediction drift), current AUC/accuracy/recall/F1, plus the drift table CSV and plots.

## Drift method and thresholds
* **Reference** = 50 % stratified training split. **Current** = 150 records drawn from the other 50 %.
  The dataset has no real time axis, so drift is **simulated**; labels stay genuine because real rows are re-selected.
* **Two-sample Kolmogorov–Smirnov test** per feature, Bonferroni-corrected: p < 0.05 / 8 = 0.00625.
* **Population Stability Index** (10 reference-quantile bins): < 0.1 stable, 0.1–0.2 moderate, ≥ 0.2 significant.
* A feature is **flagged** only if KS is significant **and** PSI ≥ 0.1 (statistically significant *and* practically meaningful).
* Alert level: `NONE` (0 features), `FEATURE_ALERT` (≥ 1 feature), `DATASET_DRIFT` (≥ 25 % of features = 2 of 8).
* **Prediction drift**: KS test between out-of-fold reference probabilities and current probabilities.
* Zeros in Glucose, BloodPressure, SkinThickness, Insulin and BMI are treated as missing values.

## Optional: run MLflow on the AWS design from ISE-1
The ISE-1 architecture hosts an MLflow server on the EC2 instance (port 5000, reached through SSM port-forwarding),
with run metadata in a separate `mlflow` PostgreSQL database on RDS and artifacts in the `medipredict-ml` S3 bucket.
This ISE-2 submission runs locally; only `--tracking-uri` changes to point at that server.

## Limitations
Drift is simulated on a 768-record public dataset; thresholds are design choices, not clinical standards.
The model is decision support only and not a medical diagnosis.
